# Hyprland dotfiles audit — 2026-09-28

Baseline: `5b9c7366a975b7680cb5b68f8ff64cc531131ac0` (`main`, also upstream main when checked).
The checkout was clean before this work. Inventory: **650 tracked files**;
167 shell entry points/libraries/tests passed `bash -n`. This inventory covers
all tracked files, including hidden files, media, templates, and fixtures.
Binary images/videos were inventoried, not decoded as executable code. Ignored
Python bytecode is listed separately. Git's internal object database is excluded.

The audit used per-file type/permission/reference checks, repository-wide secret,
path, command and ShellCheck scans, and detailed tracing of startup, deployment,
keybindings, capture, modes, and network-download boundaries. This is not a claim
that every QML UI or hardware integration was exercised.

## Environment and limits

The available host is **Debian 13**, not the target Arch desktop. Both requested
commands returned `hyprctl: command not found`: `hyprctl version` and
`hyprctl configerrors`. `Hyprland`, Quickshell, Stow, and pacman are also absent.
Consequently **no clean live configerrors result or installed Hyprland version
can be asserted**. Lua syntax and non-mutating binding replay are checked; they
cannot validate compositor API semantics. The config itself mentions 0.55+ and
0.56.2. Current official docs and the upstream 0.56.2 source were consulted.

ShellCheck 0.10.0, Lua 5.4.7, and strace were extracted from Debian packages under
`/tmp` for checks; no system packages were installed. No Stow deployment, desktop
reload/restart, bootloader command, firewall mutation, or real network download
was performed by the tested scripts. All mutating paths were tested with command fixtures and temporary
state. There are no tracked alpm hooks, UEFI boot entries, or machi-specific files.

## Startup and execution map

1. `system/greetd/config.toml` starts a **separate greeter-user** compositor with
   `conf/greeter/hyprland-greeter.conf`. Its sole active `exec-once` runs
   `regreet; hyprctl dispatch exit`: the exit waits for regreet. GTK portals are
   disabled in that greeter to avoid negotiation delays. The path is host-specific
   and requires greeter-user traversal permissions (not verifiable here).
2. The authenticated session loads `hyprland.lua`. It registers a fallback
   monitor, environment, input, gestures, window rules and binds, then loads
   generated decoration and optional monitor/workspace modules. Theme generation
   must happen before the first login; `conf/decorations.lua` is not tracked.
   greetd does not source `.zshrc`; the Lua entry point adds `~/.local/bin` to PATH.
3. `conf/autostart.lua` registers one `hyprland.start` callback. Its **launch**
   order is wallpaper restore; text clipboard watcher; image clipboard watcher;
   Quickshell; hypridle-profile; desktop-mode daemon; Spotify notification follower;
   monitor watcher; polkit service start; night-light timer start; Helium (2);
   Spotify (9); virt-manager (6); Hermes (6); Obsidian (3); T3 Code (4);
   Kitty → Zsh → herdr (1); udiskie. These calls launch asynchronously. Source
   order does not establish readiness dependencies between them.
4. Wallpaper restore starts hyprpaper if absent and retries its IPC up to
   40 × 50 ms. It blocks only its own helper. Quickshell has no dependency on
   wallpaper readiness. The two `wl-paste --watch` processes invoke the secret
   filter on changes, then `cliphist store`; they do not poll.
5. Quickshell loads `shell.qml`, the bar, desktop clocks, notification server,
   video-download UI, and QR overlays. Its native MPRIS, PipeWire and UPower
   objects provide media/audio/battery data. Other panels invoke the scripts
   identified in the inventory and `menu/.config/lmenu/menu.jsonc`.
6. `hypridle-profile daemon` renders a selected profile and execs hypridle. The
   balanced profile starts a screensaver after 180 seconds, locks at 300, turns
   displays off at 1200, and suspends at 1800. Audio/mode conditions gate the
   screensaver/lock. Pre-suspend locking is delegated to loginctl with
   `inhibit_sleep = 3`; resume restores DPMS. Runtime authentication was not tested.
7. `hypr-monitor-watch.py` connects to socket2 (bounded 30-second startup retry,
   five-second reconnect retry), debounces events by 0.6 seconds, then synchronously
   runs the profile applier. The applier samples every 0.4 seconds for up to ten
   seconds and serializes writes. This blocks the watcher/applier, not Hyprland
   startup. Replacing this with a systemd path unit would lose socket events.
8. `desktop-mode` reconciles DND and expires temporary modes every two seconds.
   Its wait loop wakes in 0.1-second increments; a future signal/event wait could
   reduce wakeups. The shader helper now owns night-light state, shared by modes,
   keybinds and the schedule, so reconciliation does not undo external changes.
9. `spotify-notify.sh` follows playerctl events, not a polling loop. Art retrieval
   now has a five-second bound and falls back to a text notification.

`hyprland.conf` sources the retained hyprlang graph: `var.conf`,
`keybinding.conf`, `windows-rules.conf`, `autostart.conf`, then generated
`decorations.conf`, `monitors.conf`, and `workspaces.conf`. This is a rollback
configuration, not a second concurrent user startup path. Its autostart differs:
it explicitly launches the separate cava visualizer and starts the monitor
watcher through systemd; it lacks the Lua night-light timer launch. No active
`exec-once-refresh` lines were found. The greeter has its own `exec-once` above.

Tracked systemd files:

| Unit | Execution / lifecycle |
| --- | --- |
| `hypr-monitor-watch.service` | Executes the socket watcher; `PartOf` and `After=graphical-session.target`; restart on failure after 3 s. The active Lua startup launches the script directly instead. |
| `night-light-schedule.service` | Oneshot `night-light-schedule.py apply`. |
| `night-light-schedule.timer` | Started by Lua autostart; immediate and minutely checks, 5 s accuracy. No session `PartOf` is declared; with a lingering user manager it can outlive the graphical session. |
| `swaync.service` | Empty file: deliberate systemd mask. Quickshell owns notifications. |

Current upstream Hyprland imports the systemd/D-Bus environment itself. Its
0.56.2 `Compositor.cpp` launches that import asynchronously. No new artificial
wallpaper/bar dependency or global startup sleep was added. Whether this target
build activates the session target and completes environment import before the
explicit service starts still requires an actual session check.

Keybinds route through `conf/keybindings.lua`, with `conf/variables.lua` supplying
programs and script paths. `run-if-deployed.sh` gates optional Stow packages;
`run-or-install` offers installation for named apps. Lua replay expands loops
and verifies unique chords. SUPER+Q deliberately means close-window; Hyprland's
emergency/default terminal binding is not an extra binding layered on top.
The 15-second Gaming VM wait is on-demand, not a login stall. Reload helpers and
mode/profile changes contain bounded shutdown/readiness waits, also off the
login critical path.

## Security, paths and Stow checks

No tracked private keys or real credential literals were confirmed by the
pattern scan. The Windows password matches were a test fixture and a variable
being written to a private temporary env file; neither was a leaked credential.
The fast.com API token is documented as a public API constant. No world-writable
tracked file or tracked symlink was found. The SSH fragment enables keepalives,
not agent forwarding; the autossh wrapper validates host/session arguments and
has bounded SSH connection timeouts. Per-host IdentityFile/IdentitiesOnly rules
belong in the user's untracked SSH configuration. The GPG examples document
confirmation and TTL limits.

A read-only destination comparison found **515 undeployed candidate package
files, no duplicate package destinations, and no existing conflicting/broken
live links at those destinations** on this host. This is not a GNU Stow dry run
or proof that the separate Arch home is conflict-free. Native host and greeter
paths, generated theme files and optional binaries must be checked there.

Missing startup binaries here: start-hyprland, Hyprland, hyprctl, quickshell,
hyprpaper, hypridle, wl-paste, cliphist, playerctl, hyprpolkitagent,
helium-browser, spotify, virt-manager, obsidian, t3code, kitty, zsh, herdr,
udiskie, hyprlock, wpctl and pactl. Hermes, systemctl, loginctl, notify-send and
dbus-update-activation-environment exist. These are host-environment findings,
not evidence that the Arch configuration should have its applications removed.
